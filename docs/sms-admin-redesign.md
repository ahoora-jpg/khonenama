# بازطراحی مرکز پیامک خونه‌نما

تاریخ: ۲۷ اکتبر ۲۰۲۶

## دامنه و مبنا

مبنای تغییرات `a57f01b6fbc45fac92e6ae6400edf6a4b3fe02a3` روی شاخهٔ اصلی است. PR ۴۴ مبنای جاری نبود؛ تغییرات ورود، حالت خاموش ارسال و دامنه از PRهای ۴۹ تا ۵۲ حفظ شده‌اند. بازطراحی فعلاً روی شاخهٔ `feat/sms-admin-redesign` است و منتشر نشده است.

سامانهٔ فعلی با Next/vinext، Worker، پایگاه D1 و عامل ویندوز کار می‌کند. معماری، پایگاه، منطق صف، رضایت، اتصال گوشی و سیم‌کارت دوم بازنویسی نشده‌اند. مهاجرت پایگاه یا وابستگی اجرایی تازه‌ای لازم نیست. اطلاعات تصویر مرجع وارد سامانه نشده‌اند؛ دادهٔ آزمون فقط در SQLite حافظه‌ای ساخته و پس از آزمون بسته می‌شود.

## صفحه‌ها

| مسیر | کارکرد |
|---|---|
| `/sms` | شش کارت آمار واقعی، فعالیت روزانه، آخرین پیام‌ها و کمپین‌ها، وضعیت عامل و دسترسی سریع |
| `/sms/send` | فرم مستقل، انتخاب مخاطب، نوع، دلیل عملیاتی، متن، شمارش بخش‌ها و پیش‌نمایش |
| `/sms/contacts` | جست‌وجو، فیلتر رضایت، صفحه‌بندی، افزودن، ویرایش مشخصات و سابقهٔ رضایت |
| `/sms/groups` | گروه، تغییر نام، تعداد کل/مجاز، مدیریت عضو و ورود CSV |
| `/sms/campaigns` | فهرست، جست‌وجو/فیلتر، پیشرفت ثبت در صف، ساخت شش‌مرحله‌ای و تأیید تغییر وضعیت |
| `/sms/templates` | فهرست، جست‌وجو، ویرایش در پنجره، متغیرها و پیش‌نمایش خام |
| `/sms/inbox` | جست‌وجو و صفحه‌بندی پیام‌های دریافتی |
| `/sms/history` | جست‌وجو، فیلتر وضعیت، صفحه‌بندی، جزئیات رویداد و لغو پیام مجاز |
| `/sms/reports` | بازهٔ تاریخ، نمودار و جدول واقعی، نوع پیام، وضعیت، رضایت و لغو عضویت |
| `/sms/gateway` | وضعیت واقعی عامل، آخرین ارتباط، سیم‌کارت و مراحل اتصال امن |
| `/sms/settings` | وضعیت دسترسی، محدودیت‌ها، نگهداری داده و عیب‌یابی امن |

ورود `/sms/login` و `/login` حفظ شده و دکمهٔ چشم/پشتیبانی از تکمیل خودکار رمز باقی است. مسیر قدیمی `/admin/sms` به `/sms` منتقل می‌شود. آدرس با `www` همچنان به آدرس اصلی منتقل می‌شود. میزبان پیامک فقط ده مسیر جدید شناخته‌شده را علاوه بر مسیرهای قبلی می‌پذیرد؛ هر مسیر دلخواه زیر `/sms/` مجاز نشده است.

## اجزای مشترک

`components/sms/SmsAdminShell.tsx`: پوسته، منوی سمت راست، سربرگ، وضعیت عامل، حساب/خروج، بازخوانی اطلاعات، کنترل ورود، کشوی موبایل با مدیریت تمرکز، اعلان، کارت آمار، وضعیت، پنجره، فرم، جست‌وجو، صفحه‌بندی، حالت خالی و بارگذاری.

`SmsApplication.tsx`: اتصال صفحه‌ها به پوسته و مرز بارگذاری.

`SmsOverview.tsx`: داشبورد، نمودار با جدول جایگزین، گزارش، اتصال و تنظیمات.

`SmsMessages.tsx`: فرم پیام، تاریخچه و دریافتی‌ها.

`SmsContacts.tsx`: مخاطبان، رضایت و گروه‌ها.

`SmsCampaignWorkspace.tsx`: کمپین مرحله‌ای و قالب‌ها.

`lib/sms-admin-ui.ts`: فهرست مسیرها، عنوان‌های فارسی، قالب تاریخ تهران، قالب عدد و تشخیص تازگی ارتباط عامل.

`app/sms/sms.css`: رنگ‌ها، اندازه‌ها، جدول‌ها، فرم‌ها، کشو و چیدمان‌های تطبیقی؛ سبک‌ها به پنل محدود هستند.

## تغییرات حداقلی API

- `GET /api/admin/sms/workspace`: نماهای مخاطبان/جزئیات/گروه‌ها/تاریخچه/دریافتی/گزارش. همان ورود مدیریتی، محدودهٔ مستأجر، خروجی بدون کش و پوشاندن شماره‌ها را دارد. جست‌وجو با پارامتر SQL انجام می‌شود.
- API قبلی: شمارش دقیق کمپین‌های فعال، گزارش تکراری‌بودن شماره و ویرایش نام/نوع مخاطب. شماره در ویرایش ثابت می‌ماند تا رضایتِ شمارهٔ قدیمی به گیرندهٔ جدید منتقل نشود.
- API کمپین قبلی: تغییر نام گروه و حذف عضو، با کنترل مستأجر و ثبت رویداد مدیریتی. این عملیات رضایت را ایجاد یا حذف نمی‌کنند.
- هیچ تغییری در معنای وضعیت‌ها، برداشت صف، ارسال، تطبیق نتیجه یا عامل ویندوز داده نشده است.

## محدودیت‌های صریح

- آزمون چشمی مرورگر، کلیک/تکمیل خودکار و اندازه‌های واقعی ۱۴۴۰، ۷۶۸، ۳۹۰ و ۳۲۰ هنوز انجام نشده است: ابزار مرورگر با `transport closed before response` در دسترس نبود. آزمون رندر ساختاری جایگزین تأیید چشمی نیست. اسکرین‌شات تکمیل‌شده نداریم.
- انتخاب سریع گیرنده و عضو از ۱۰۰ مخاطب آخر انجام می‌شود؛ فهرست کامل مخاطبان صفحه‌بندی دارد. مدیریت اعضای گروه فعلاً حداکثر ۲۰۰ عضو اول و فهرست گروه‌ها حداکثر ۵۰۰ گروه را نشان می‌دهد. کمپین‌ها ۵۰ مورد آخر هستند. این سقف‌ها در رابط مشخص شده‌اند.
- کمپین موجود فقط تبلیغاتی، تک‌گروهی است. سرعت در عامل کنترل می‌شود؛ رابط تنظیم سرعت یا کمپین عملیاتی جدید به موتور اضافه نکرده است.
- پیام دستی زمان‌بندی مستقل ندارد. هزینه، نرخ تبدیل، زمان آخرین ارتباط موفق خود گوشی و درصد دسترس‌پذیری تاریخی موجود نیستند؛ جعل نمی‌شوند.
- بازهٔ گزارش با روزهای زمان هماهنگ جهانی محاسبه می‌شود؛ نمایش زمان‌های منفرد به وقت تهران است.
- نمودار، تعداد پیام‌های ایجادشده از جمله پیش‌نویس را نشان می‌دهد. پذیرش گوشی، ارسال و تحویل جدا هستند. دادهٔ تاریخی وضعیت یا موفقیت تحویل ساخته نمی‌شود.
- پنل کلیدها را تغییر نمی‌دهد. فعال‌سازی ارسال واقعی همچنان نیازمند تأیید مستقل و آزمون گوشی است.
- پروژه دستور lint پیکربندی‌شده ندارد؛ اجرای lint ادعا نشده است.

## روند پذیرش پیش از انتشار

۱. روی محیط محلی یا پیش‌نمایش امن با پایگاه جدا، بدون استفاده از پایگاه اصلی، وارد شوید. بدون ورود هیچ داده‌ای نباید دیده شود و APIها باید ۴۰۱ بدهند.
۲. در اندازه‌های ۱۴۴۰، ۷۶۸، ۳۹۰ و ۳۲۰، منو، جمع‌شدن، کشوی موبایل، بستن با Escape، گردش Tab و نبود اسکرول افقی سند را بررسی کنید. جدول‌ها مجاز به اسکرول داخلی‌اند.
۳. هر ۱۱ بخش را باز کنید؛ داشبورد نباید فرم‌های مدیریتی داشته باشد. با پایگاه خالی، حالت خالی/آمار صفر یا ناموجود باید نمایش یابد.
۴. در پایگاه آزمون، مخاطب اضافه کنید، دوباره همان شماره را وارد کنید و عدم تکثیر را ببینید. نام را تغییر دهید؛ شماره و رضایت نباید عوض شوند.
۵. جست‌وجو، فیلتر، صفحه‌بندی و تاریخچهٔ رضایت را بررسی کنید. ورود CSV و عضویت گروه نباید رضایت ایجاد کند. حذف عضو نباید سابقهٔ رضایت را پاک کند.
۶. پیام را ذخیره کنید: فقط `draft`، یک رویداد و بدون ارتباط با گوشی. جزئیات و لغو مجاز را بررسی کنید. دادهٔ تحویل تنها با رویداد واقعی دیده شود.
۷. شش مرحلهٔ کمپین را تکمیل کنید؛ فقط پیش‌نویس ذخیره شود. دکمه‌های فعال‌سازی و ادامهٔ ارسال باید خاموش بمانند. قالبِ ویرایش‌شده هم غیرفعال بماند.
۸. نمودار و وضعیت‌ها را با دادهٔ پایگاه آزمون تطبیق دهید؛ هیچ عدد یا مخاطب مرجع تصویری نباید وجود داشته باشد.
۹. عاملِ بدون زمان ارتباط نباید متصل نمایش داده شود. ارتباط قدیمی یا آینده به‌عنوان ارتباط اخیر نمایش داده نشود.
۱۰. خروج و انقضای نشست را بررسی کنید. سپس نسخهٔ اصلی و مسیرهای غیرپیامکی را کنترل کنید.

## انتشار و بازگشت

تا تأیید صریح مالک، این بازطراحی نباید به شاخهٔ اصلی ادغام یا در محیط اصلی منتشر شود. بعد از تأیید، آخرین Git/دستورهای مخزن بررسی، آزمون‌ها اجرا و همان روند موجود انتشار استفاده شود. `SMS_LIVE_SEND_ENABLED=false` حفظ شود. دامنه‌های سفارشی اصلی و `www.sms.khonenama.ir` هر دو باید در پیکربندی انتشار باقی بمانند. بازگشت با انتشار کد قبلی ممکن است؛ مهاجرت تازه‌ای وجود ندارد.

## نتایج واقعی بررسی این نسخه

- ۲۵ آزمون خودکار پیامک، امنیت و رندر ساختاری موفق؛ صفر شکست.
- `npx tsc --noEmit` موفق.
- `npm run build:vinext` موفق.
- `npm run check:vinext` موفق، با هشدار قبلیِ پشتیبانی جزئی از `reactStrictMode` در App Router؛ مسئلهٔ ناسازگاری جدید گزارش نشد.
- اجرای واقعی بستهٔ ساخته‌شده با Wrangler 4.145.0، پایگاه D1 محلی جدا و ارسال خاموش: هر ۱۱ صفحه و صفحهٔ ورود وضعیت ۲۰۰؛ مسیر قدیمی مدیریت وضعیت ۳۰۷.
- ورود با کلید موقت محلی و خروج موفق. هر ۹ مسیر API بررسی‌شده پس از ورود ۲۰۰؛ API جدید بدون ورود ۴۰۱. هیچ مخاطب، پیام یا کمپین در پایگاه اصلی ساخته نشد.
- سرور عمومی Node (`vinext start`) به دلیل واردکردن `cloudflare:workers` محیط مناسب این پروژه نیست؛ آزمون اجرا با محیط Worker محلی انجام شد. در شبیه‌سازی HTTP محلی، هدر HTTPS پراکسی برای جلوگیری از انتقال اجباری پروتکل استفاده شد؛ سیاست HTTPS نسخهٔ اصلی تغییر نکرد.
- آزمون چشمی مرورگر/موبایل و اسکرین‌شات هنوز انجام نشده‌اند و نباید از این نتایج استنتاج شوند.
